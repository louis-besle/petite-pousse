> **For agentic workers:** Implement this plan task by task. This repository forbids

**Goal:** Ship the selected v1.1 increment: batch bilan generation, password-encrypted backups, the official EVAR programme, real-device accessibility validation material, and technical polish.

**Architecture:** Keep the local-only PWA architecture. Batch generation composes the existing `buildBilanModel` + `generateBilanPdf` per pupil and streams the PDFs into one ZIP. Encrypted backups extend the existing ZIP format with per-entry AES-GCM encryption and a plaintext manifest, while remaining backward compatible with unencrypted backups. EVAR is modelled as a seventh programme category (`evar`) alongside the six 2026 domains so it flows through capture, programme, dossiers, and bilans without a parallel data path.

**Tech Stack:** React 19, Vite, TypeScript, Dexie/IndexedDB, pdf-lib, fflate, Zod, WebCrypto, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-06-livret-suivi-apprentissage-design.md`

## Global Constraints

- No `git commit`, `git push`, merge, or deploy without explicit user approval.
- Everything stays local: no account, no application server, no analytics, no network request for user data.
- French UI, French dates, accessible names in French.
- WCAG 2.1/2.2 AA and RGAA 4.1.2 remain the target; the PDF stays untagged and the HTML A4 preview stays the documented accessible alternative.
- Existing unencrypted backups must remain restorable.
- The app must keep working offline after the first load.
- Every new behaviour gets a Vitest test; critical flows get a Playwright test.
- Do not regress the existing gate: lint, typecheck, unit tests, build, E2E and offline E2E all stay green.

## Decisions taken for this increment

1. **Batch bilans (2.1):** one ZIP per selected year/period, containing one PDF per pupil in the class, including pupils with zero réussites (their PDF states “Aucune réussite sur cette période”). PDFs are generated sequentially to bound memory. ZIP entry names reuse `pdfFileName`. The ZIP is downloaded, not shared, for predictable behaviour on iOS.
2. **Encrypted backup (2.2):** optional password at export. Per-entry AES-256-GCM with a fresh 12-byte IV per entry; PBKDF2-SHA256, 310 000 iterations, 16-byte salt. A plaintext `manifest.json` carries KDF parameters and a verification token. No recovery: losing the password makes the backup unreadable. Minimum password length 8, with confirmation and a clear warning. Unencrypted backups keep working.
3. **EVAR (2.8):** official programme “Éduquer à la vie affective et relationnelle à l’école maternelle”, BO n° 6 du 6 février 2025. Modelled as a seventh `Domain` named `evar`, with three competencies (the three axes) and nine objectives (three per age band), sourced from the official programme. Display label “EVAR”, long label “Éducation à la vie affective et relationnelle”. Referential version becomes `2026.2.0`.
4. **Real screen-reader validation (1.1):** no physical device is available in this environment, so this increment delivers a complete manual protocol for VoiceOver (iOS/iPadOS) and TalkBack (Android), plus an automated WebKit smoke suite. The audit verdict stays “partiellement conforme” until the protocol is executed on hardware.
5. **Technical polish (3):** version `1.1.0`, WebKit Playwright coverage for the iOS/iPadOS primary target, PDF viewer metadata (display title, language), README and audit documentation refreshed. The working name “Carnet de réussites” stays until the user chooses a final name.
6. **Test counts:** expected new unit tests: batch (≥4), encryption (≥6), EVAR (≥5), polish (≥2). Final counts must be reported from actual runs, not guessed.

### Task 2: Password-encrypted backups

**Files:**
- Modify: `src/features/settings/backup.ts`
- Modify: `src/features/settings/backup.test.ts`
- Modify: `src/features/settings/BackupPanel.tsx`
- Modify: `src/features/settings/BackupPanel.test.tsx`
- Modify: `src/features/settings/settings.module.css`
- Modify: `e2e/backup.spec.ts`

**Interfaces:**
- `exportBackup(onProgress: (ratio: number) => void, options?: { password?: string }): Promise<Blob>`
- `readBackup(file: File, onProgress: (ratio: number) => void, password?: string): Promise<BackupPackage>`
- `BackupPackage.summary.encrypted: boolean`
- `class BackupPasswordRequiredError extends BackupReadError`
- `class BackupWrongPasswordError extends BackupReadError`
- `class BackupCorruptedError extends BackupReadError` (authentication failure on an encrypted entry)

**Format:**
- Top-level `manifest.json` (plaintext, stored): `{ format: 'carnet-de-reussites-backup', version: 1, encrypted: true, kdf: { name: 'PBKDF2', hash: 'SHA-256', iterations: 310000, salt: base64 }, cipher: { name: 'AES-GCM', tagLength: 128 }, check: { iv: base64, data: base64 } }`.
- Every other entry (data.json, referential.json, photos/*.jpg, thumbs/*.jpg) is `12-byte IV || AES-GCM ciphertext`.
- PBKDF2 derives a 256-bit AES-GCM key from the UTF-8 password.
- The check token is the encryption of `carnet-de-reussites` with the derived key; a failed check means wrong password.
- Encrypted entries use `ZipPassThrough` (no deflate) so encryption happens once per file and memory stays bounded.
- `readBackup` detects the manifest, requires a password, verifies it, decrypts entries one at a time, then runs the existing validation path unchanged.
- `schemaVersion` inside data.json stays `1`. Old unencrypted backups still restore.
- Replace the hard-coded domain enum with `z.enum(DOMAIN_IDS)` imported from `@/domain/referential` so EVAR validations restore correctly.

**UI:**
- Export card gains a checkbox “Protéger par un mot de passe” and, when checked, password + confirmation fields (min 8 chars) with show/hide controls.
- Warning: “Sans ce mot de passe, la sauvegarde est définitivement illisible. Il n’existe aucun moyen de le récupérer.”
- Export filename gains `-chiffre` when encrypted.
- Import: if `readBackup` throws `BackupPasswordRequiredError`, open a password sheet (use `Sheet` + `Field`) named “Sauvegarde chiffrée”; submit retries with the password; wrong password shows an inline French error and keeps the sheet open; cancel clears the pending file.
- Import summary shows “Sauvegarde chiffrée” when applicable.
- Update the Settings privacy notice copy (owned by Task 5) later; do not edit `SettingsScreen.tsx` here.

**Tests:**
- Round trip: export with password → read with same password → same summary and data.
- Wrong password → `BackupWrongPasswordError`.
- Missing password → `BackupPasswordRequiredError`.
- Tampered ciphertext → `BackupCorruptedError` (GCM authentication).
- Legacy unencrypted export still reads with no password.
- Encrypted ZIP does not contain a readable `data.json` (raw bytes do not include `"schemaVersion"` in plaintext).
- UI test for required-error opening the sheet and successful retry.
- E2E: export encrypted, re-import with password, verify the confirmation dialog, then wrong-password path.
